Earlier CodeRabbit findings, all answered in the PR threads:
- Pending runs can be dropped by GitHub: the script always deploys the current tip of `origin/main`, so the next run covers them; docs say intermediate pushes may be skipped.
- An older run could move stage backward: fixed the same way.
- Manual deploys bypassed the lock: manual deploys now go through `ci-deploy.sh deploy`.
- `.deploy-history` alone is not proof stage is running: the skip also needs `deploy.sh health` to pass.

## Checked and sound

Command parsing (no injection path), forced command with `restrict`, the lock on every exit path, `set -e` behaviour, the script replacing itself on checkout, and secrets reaching the step only through `env` with `permissions: {}`.

## Why? questions, answered by the author

1. Why wait up to 600 s for the lock? A manual deploy may hold it; waiting is better than failing a CI run for that.
2. Why compare short shas in history? `deploy.sh` writes them and image tags use them; a short-sha collision in one repo is not a realistic risk here.
3. Why skip on `**.md`? No service reads markdown at build or run time.
